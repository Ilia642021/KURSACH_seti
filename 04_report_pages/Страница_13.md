# Сценарий моделирования A: Базовый режим работы

В данном разделе рассматриваются результаты моделирования сети в штатном (базовом) режиме. Основной целью этого сценария является подтверждение корректности настройки топологии, адресации и работоспособности всех узлов сети при использовании основного канала связи.

## Настройки сценария
В конфигурации `A_Base` установлены следующие ключевые параметры:
- **Основной канал (Core <-> ISP):** Активен (интерфейс `ppp2`).
- **Резервный канал:** Отсутствует (не настроен в этом сценарии).
- **Нагрузка:** 30 рабочих станций в центральном офисе (HQ), 4 станции в филиалах.
- **Трафик:** ICMP-запросы (Ping) от каждого хоста к серверу `inetHost` (10.0.5.2) с интервалом в 1 секунду.
- **Время начала трафика:** 5 секунд (задержка для сходимости протоколов маршрутизации).

## Результаты анализа
По результатам обработки логов и векторов данных (`A_Base-0.vec`) были получены следующие показатели:

1. **Маршрутизация:**
   Протокол OSPF успешно построил таблицы маршрутизации. Весь исходящий интернет-трафик направляется через интерфейс `ppp2`.
   - Подтвержденных записей о маршруте через `ppp2`: 55 (для контрольного хоста).
   - Ошибок маршрутизации или потерь пакетов не зафиксировано.

2. **Временные характеристики (RTT):**
   Среднее время круговой задержки (Round Trip Time) для хостов центрального офиса составило:
   - **Среднее RTT:** ~0.443 мс.
   - **Стабильность:** Задержка остается практически константой на протяжении всей симуляции, что свидетельствует об отсутствии очередей на интерфейсах при данной интенсивности трафика.

3. **Активность сети:**
   - Общее количество отправленных ICMP-запросов в системе: 168.
   - Процент успешных ответов: 100%.

## Доказательства корректности
В системном логе симуляции зафиксированы события отправки и получения пакетов:
```text
[INFO] Sending ping request #0 to destination 10.0.5.2
[INFO] Ping reply #0 arrived from 10.0.5.2, rtt = 0.4429 ms
[OK] Маршрут: destination = 10.0.5.2, output interface = ppp2
```

## Вывод по сценарию A
Сеть функционирует в полном соответствии с проектными требованиями. Выбранная топология и настройки OSPF обеспечивают стабильную связь всех сегментов сети с внешним сервером через основной канал. Полученные данные RTT будут использованы как эталонные для сравнения с режимами повышенной нагрузки и аварийными ситуациями.
